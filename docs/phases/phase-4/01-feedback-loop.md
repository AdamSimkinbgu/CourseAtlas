# Phase 4.1 – Feedback Collection & Iteration

## Objective
Establish structured processes for collecting, triaging, and acting on beta feedback to drive post-launch improvements.

## Tasks

1. **Feedback channels**
   - Maintain beta Slack/Discord/email form established in Phase 3.  
   - Add in-app feedback widget (e.g., `FeedbackFish`, custom form).  
   - Encourage users to submit feature requests and bugs.

2. **Issue tracking**
   - Use GitHub Issues or Linear for backlog management.  
   - Create templates for bug reports (device, steps to reproduce) and feature requests.  
   - Tag issues by priority, area (editor, import, auth).

3. **Weekly review cadence**
   - Schedule weekly review meeting (even solo: block time) to triage new feedback.  
   - Decide whether to fix immediately, schedule for future sprint, or decline with rationale.

4. **User interviews**
   - Conduct 15–30 minute interviews with select users.  
   - Prepare discussion guide focusing on pain points and success stories.  
   - Record insights in `docs/feedback/interviews.md`.

5. **Analytics & heatmaps**
   - Review analytics dashboards weekly to identify drop-offs.  
   - Optionally integrate heatmap tool (Hotjar) with consent.

6. **Roadmap updates**
   - Maintain living roadmap in `docs/roadmap.md`.  
   - Communicate upcoming improvements to beta users.

## Deliverables
- Feedback tracking system (issues board).  
- Weekly triage routine established.  
- Interview summaries and updated roadmap.
