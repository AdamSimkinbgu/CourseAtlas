# Phase 3.5 – Beta Launch Preparation

## Objective
Coordinate the tasks necessary to run a controlled beta, gather feedback, and iterate quickly.

## Steps

1. **Beta program definition**
   - Determine cohort size (e.g., 20–30 users).  
   - Outline goals (validate usability, gather course coverage feedback).  
   - Draft NDA or terms if required.

2. **Landing page & sign-up**
   - Build simple marketing page describing value proposition.  
   - Include email capture form (Mailchimp, ConvertKit).  
   - Provide timeline and expectations for beta participants.

3. **Invitation workflow**
   - Create email template with onboarding instructions.  
   - Provide unique invite codes or staged rollout via auth provider (e.g., allowlisted emails).  
   - Set up referral/invite tracking.

4. **Support channels**
   - Create dedicated Slack/Discord or email alias for feedback.  
   - Add in-app “Send feedback” button posting to issue tracker or form.

5. **Feedback loop**
   - Prepare survey (Google Forms, Typeform) for initial impressions.  
   - Schedule weekly check-ins, review analytics + qualitative feedback.  
   - Triage issues into GitHub Issues or Kanban board.

6. **Release notes & onboarding docs**
   - Publish `CHANGELOG.md` entry summarizing beta features.  
   - Update `docs/user-guide.md` with how-to articles (creating graphs, using templates).  
   - Record short screencast demo.

7. **Operational readiness**
   - Confirm monitoring/alerts configured (from Phase 3.2).  
   - Set up incident response runbook (who responds to downtime).  
   - Rehearse disaster recovery (restore from backup).

8. **Launch day checklist**
   - Deploy latest builds to staging → production.  
   - Smoke test critical flows.  
   - Send invites, monitor logs closely.  
   - Gather first-day feedback, fix high-priority issues.

## Deliverables
- Beta landing page with sign-up.  
- Invite/onboarding materials.  
- Feedback channels and tracking system.  
- Public beta announcement plan.
